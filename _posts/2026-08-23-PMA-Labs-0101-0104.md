# Lab 01-01
## Question 1 - Upload the files to http://www.virustotal.com/ and view the reports. Does either file match any existing antivirus signatures?
Both of the files match against 56/71 Lab01-01.exe and 39/71 Lab01-01.dll AV vendors respectively available on VT.
## Question 2 - When were these files compiled?
Lab01-01.exe was compiled on 19.12.2010 16:16:19 UTC.
Lab01-01.dll was compiled on 19.12.2010 16:16:38 UTC.
## Question 3 - Are there any indications that either of these files are packed or obfuscated? If so, what are the indicators?
No, a regular amount of dll/function imports are available and there are visible strings in the program and dll.
## Question 4 - Do any imports hint at what this malware does? If so, which are they.
Kernel32.dll is imported by both the dll and the exe.
The exe imports File manipulation related functions such as CreateFileA,CopyFileA,FindNextFileA etc.
The dll imports CreateProcessA and sleep so we know it will be spawning a new process.
## Question 5 - Are there any other files or host-based indicators that you could look for on infected systems?
Possibly a file by the name of C:\Windows\System32\kerne132.dll imitating kernel32.dll.
## Question 6 - What network-based indicators could be used to find this malware on infected machines?
127.26.152.13 seems to be an ip address located at offset 0x26028 in the dll.
## Question 7 - What would you guess is the purpose of these files.
One idea is that it could possibly replace the kernel32 linkages with the fake kerne132.dll in all of your files.

## Note 
The dll also imported WS2_32.dll which provides network functionality, but they are imported by ordinal so we do not know which functions.
There are exec and sleep strings located in the dll itself so it is probably a command runner which runs something via CreateProcess when command matches exec (strncmp is imported too), so the malware is probably a backdoor.
